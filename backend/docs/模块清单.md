# 线上洗车平台 v6.0 · 模块清单

> 本文基于实际工程结构（`pom.xml`、`clients/`）与 PRD v6.0「图 8 软件功能模块分层架构」整理。
> 后端 Java 代码由后端工程师实现，文中包路径为**约定落点**（`com.xiche.<业务域>`），最终以实际提交为准。
> 部署与运行见 `../DEPLOY.md`；架构分层与请求链路见 `架构说明.md`。

## 1. 工程模块树

```
<工程根>/                              父工程 xiche-platform（packaging=pom）
├── pom.xml                            统一依赖版本：Spring 5.3.30 / MyBatis 3.5.13 /
│                                      mysql-connector-j 8.0.33 / Druid 1.2.20 /
│                                      Jackson 2.13.5 / Servlet 4.0.1，Java 1.8
│
├── xiche-common/                      【公共模块】无业务，被所有模块依赖
│   └── src/main/java/com/xiche/common/
│       ├── constant/                  业务常量、状态枚举、错误码
│       ├── exception/                 全局异常与业务异常
│       └── util/                      通用工具（时间、金额分/元转换、校验）
│
├── xiche-pojo/                        【实体模块】DTO / VO / Entity，无业务逻辑
│   └── src/main/java/com/xiche/<业务域>/entity/
│
├── xiche-dao/                         【持久层模块】MyBatis Mapper 接口 + XML
│   ├── src/main/java/com/xiche/<业务域>/dao/
│   └── src/main/resources/mapper/<业务域>/   映射 XML（手写 SQL，参数化防注入）
│
├── xiche-service/                     【业务层模块】14 个业务域服务与实现
│   └── src/main/java/com/xiche/<业务域>/service/  及 service/impl/
│
├── xiche-web/                         【表现层模块】★ 唯一打 war 的模块
│   ├── src/main/java/com/xiche/<业务域>/controller/   REST Controller（/api/ 前缀）
│   ├── src/main/resources/
│   │   ├── jdbc.properties            数据库连接（部署时改写，见 DEPLOY.md 第 4 节）
│   │   ├── spring-*.xml                Spring / SpringMVC / MyBatis / 事务配置
│   │   └── logback.xml                日志配置
│   └── src/main/webapp/WEB-INF/views/admin/   后台管理端 JSP 页面
│
├── clients/                           【三端源码】由前端工程师实现
│   ├── miniprogram/                   微信小程序
│   ├── app/                           App（用户 / 洗车工 / 门店三类角色页面）
│   └── h5/                            H5（移动端网页）
│
├── sql/
│   ├── 01_schema.sql                  建表结构
│   ├── 02_init_data.sql               基础数据（角色 / 权限 / 字典）
│   └── 03_test_data.sql               V1 测试数据（含 admin/admin123，禁止用于生产）
│
├── docs/
│   ├── 模块清单.md                    本文
│   └── 架构说明.md                    SSM 分层 / 请求链路 / 支付 / 缓存 / 认证
│
├── 一键部署.bat / 一键启动.bat / 一键停止.bat / 数据库初始化.bat
├── README.md                          工程总入口
└── DEPLOY.md                          Windows 部署手册
```

**模块依赖方向（禁止循环依赖）**：

```
xiche-web  ──▶  xiche-service  ──▶  xiche-dao  ──▶  xiche-pojo  ──▶  xiche-common
     └──────────────────────────────────────────────────────────────┘
```

- 上层可依赖下层，**下层禁止反向依赖上层**；
- `xiche-common` 不得依赖任何业务模块；
- 跨域调用统一经过 `xiche-service`，Controller 不直接调 Mapper。

## 2. 十四个业务域（PRD v6.0 图 8）

业务域层共 **14 个中心/引擎**，其中 3 个为 v6.0 新增（标 ★）。服务均落在 `xiche-service`，接口落在 `xiche-web` 的 Controller，数据落在 `xiche-dao`。

| # | 业务域（PRD 定义） | 职责摘要 | 约定代码包 | 来源 |
|---|--------------------|----------|------------|------|
| 1 | 服务目录中心 | 三档品类（外观/标准/精细）、增值项、上门能力边界 | `catalog` | v1~v5 演进 |
| 2 | 工时与产能中心 | 标准工时、门店 Bay/Crew 产能与预约占用 | `store` / `order` | v5 |
| 3 | 产能状态中心 | Bay/Crew 状态机、心跳与事件驱动、并发锁位不超卖 | `store` | v5 |
| 4 | 定价引擎 | 三档价、上门价、增值项计价、价格版本与快照 | `order` / `catalog` | v3~v4 |
| 5 | 订单中心（双形态） | STORE 到店单 + ONSITE 上门单，状态机与证据链 | `order` | v1~v5 |
| 6 | 派单中心 | 抢单池、指派、权重与失败短路可解释 | `order` / `worker` | v1~v5 |
| 7 | 计价与结算中心 | 分账公式、抽成、对账、结算报表 | `settlement` | v3 |
| 8 | 上门单中心 | 上门大厅、场地确认、污水与物业合规校验 | `order` | v5 |
| 9 | 分成比例与公示中心 | 比例版本、公示、变更通知、`rate_snapshot` | `commission` | v3 |
| 10 | 评价与治理中心 | 门店五维评价、差评降权不扣报酬、申诉与拉黑复核 | `governance` | v3~v5 |
| 11 | 保险与证据中心 | L1 强制 / L2 可选保单、E1~E4 证据、事故冻结结算 | `insurance` | v1~v4 |
| 12 | ★派单资格中心 | 六项合取谓词、认证门槛、二次核对主库、可解释失败 | `learning` / `auth` | **v6 新增** |
| 13 | ★学习考试中心 | 课程包、SOP 差异重训、组卷考试、补考与申诉 | `learning` | **v6 新增** |
| 14 | ★认证等级中心 | C1/C2/C3/D/O 证书、有效期、复审与吊销 | `learning` / `auth` | **v6 新增** |

**配套横切包**（不属于 14 业务域，但是平台运转必需）：

| 包 | 职责 |
|----|------|
| `user` | 车主账号、登录态、资料脱敏 |
| `worker` | 洗车工档案、抢单行为、本人结算查询 |
| `payment` | V1 **模拟支付**流水与状态机（不接真实渠道） |
| `coupon` | 优惠券领取、核销与防刷 |
| `auth` | RBAC 角色/权限/数据范围、JWT 鉴权与拦截器 |
| `cache` | 缓存键规范、失效广播、快照与降级（见架构说明） |

> 业务域依赖原则：派单资格中心是**派单前置校验**的合取点，派单中心不得绕过它直接把订单放入抢单池；评价/认证等减损权益的处置必须人工复核，禁止算法自动终局处置（PRD 第 6.3 / 8 章）。

## 3. 各端目录说明

PRD 图 8 的接入层为**四端**：用户端 App、洗车工端 App、门店端工作台、后台管理端 Web；工程落地为 `clients/` 三套前端工程 + `xiche-web` 内置后台页面。

### 3.1 微信小程序 `clients/miniprogram/`

```
app.js / app.json / app.wxss        全局配置：baseURL、登录态、模拟支付环境标记
pages/
├── user/                          车主端：下单、支付（模拟）、订单、评价、申诉
├── worker/                        洗车工端：抢单、接单、证据上传、学习考试
├── store/                         门店端：产能开关、上门大厅、工位验收
└── common/                        公共页：登录、我的、消息
utils/
├── api.js                         统一请求封装：拼 baseURL、带 Bearer Token、解包 {code,msg,data}
└── constants.js                   业务常量：BASE_URL、三档价格（单位分）、保险档位
```

- **金额口径**：后端一律以「分」传输，前端用 `fen2Yuan()` 转换；
- **支付口径**：V1 模拟支付成功文案为橙色「模拟支付成功」，严禁绿色「支付成功」；
- **baseURL**：默认 `/api/`，联调改为 `http://<本机IP>:8080/api/`（详见 `../DEPLOY.md` 第 7 节）。

### 3.2 App `clients/app/`

```
common/                            全局配置与请求封装（baseURL、Token、金额转换）
pages/
├── user/                          用户端页面
├── worker/                        洗车工端页面
└── store/                         门店端页面
static/                            图片、图标等静态资源
```

- 一套工程承载三类角色页面，通过角色（RBAC）控制可见菜单与数据范围；
- 明文 HTTP 仅用于测试版，Android `usesCleartextTraffic` / iOS `NSAppTransportSecurity` 配置见部署手册 7.3。

### 3.3 H5 `clients/h5/`

```
css/                               样式
js/                                请求封装与业务脚本（baseURL 配置点）
```

- 面向轻量访问与活动页；与后端不同源时需 CORS 或开发代理；
- 浏览器兼容基线：Chrome / Edge / Safari 主流两版 + 移动端浏览器。

### 3.4 后台管理端 Web `xiche-web/src/main/webapp/WEB-INF/views/admin/`

- 与后端同源部署，API 使用相对路径 `/api/`，无需改 baseURL；
- 角色包括超级管理员、运营、审核、财务、客服、法务合规、城市经理、审计员（详见架构说明 RBAC 章节）。
