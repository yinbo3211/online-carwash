## 二、P0 阻断级缺陷（7 项，全部修复）

| 编号 | 缺陷 | 修复要点 | 回归用例 |
|------|------|----------|----------|
| P0-01 | 模拟支付必失败/保单不出单 | 根因：父 pom 未开 `<parameters>`，Mapper 具名参数无法解析。修复：pom 开启 `<parameters>true</parameters>` + 全部多参 Mapper 补 `@Param` | B2/B5：支付 200、t_policy 新增 1 行 |
| P0-02 | 洗车工抢单必失败 | `OrderMapper.assignWorker` 等补 `@Param`，XML `paramN` 统一改具名 | C3：抢单成功 |
| P0-03 | 门店工位状态修改失败 | `StoreBayMapper.updateStatus/lockBay/releaseBay` 补 `@Param` | D2：工位三态可切换 |
| P0-04 | 收入页 SQL 列歧义 | `SettlementMapper.selectByWorker` 的 `SELECT` 显式给所有列加 `s.` 前缀（原 `s.<include>` 仅首列带前缀） | C15：收入页 200 |
| P0-05 | 身份由请求头伪造 + 强制 ADMIN | 新增统一账号表 `t_account` + 登录端点 `/api/auth/login` + HMAC-SHA256 签名令牌；`AuthInterceptor` 重写：唯一信任 `X-Token`，从库加载角色，**删除 `roles.add("ADMIN")`**，越权记审计 | F1~F6/E3：伪造头全被拒，无 token 401 |
| P0-06 | 幂等键跨用户订单劫持 | `orderNo` 改服务端生成（不含 requestId）；幂等改 `(user_id, request_id)` 联合唯一 + 归属限定查询 | A4/A5：跨用户复用不再命中他人订单 |
| P0-07 | 履约状态推进与结算触发整体缺失 | 新增 `OrderService.progress()`：按状态机推进，完工(80)事务内触发 `settle()` + 释放工位 + 重算评分；E4 后自动推进完成；支付端补归属校验 | C8/C9：完工触发结算落库、恒等式成立 |
