一、本版修订说明与口径回显

1.1 已确认口径（本轮不漂移）

口径变更（唯一实质变更，须评审确认）：门店进场后，原「抽成基数 = 洗车服务收入 S」不再适用。因为门店工位费要么从 S 中划出、要么由平台另付，继续按 S × 40% 抽成会造成洗车工实收被双重挤压或平台毛利倒挂。本版给出 A/B 两套方案，推荐 A：抽成基数改为 L = S − M（洗车工劳务收入），M 为代收代付的门店工位费、不抽成。这与 v1.0「保险费不抽成」的口径逻辑一致，40% 仍然是「抽洗车工的劳务」，不是抽门店费。若评审坚持 40% 名义不变，可按 1.2 的配置切换，不影响已生成订单。

1.2 抽成基数 A/B 方案对比与推荐

方案抽成基数公式与现金流优点缺点结论
AL = S − Mplatform_fee = L × r
worker_net = L − fee + D
store_net = M
恒等式：P + C = worker + store + B + fee		与「保险费不抽成」口径一致；40% 仍针对洗车工劳务；M 由 BD 协议独立谈，恒等式干净，对账只需一套口径平台运营费绝对值下降（基数变小），需重新测算单位经济模型推荐
BS（不变）platform_gross_fee = S × r
worker_net = S − fee + D
store_net = M 由平台从毛运营费中支付
platform_net = S×r − M		用户、洗车工、抽成名义三个口径全部不变，改动面最小需新增「毛运营费 / 净留存」两个口径；M 上升会侵蚀平台净收入，M > S×40% 时倒挂；门店费成为平台成本而非代收代付，财务与对账复杂度上升备选

数值对照（虚构示例，S=¥100、M=¥20、B=¥6、D=¥10、C=¥15、r=40%）：方案 A 下 fee=¥32、worker=¥58、store=¥20、P=¥101，平台净留存 ¥32；方案 B 下 毛 fee=¥40、worker=¥70、store=¥20，用户实付仍 ¥101，但 P + C = ¥116 ≠ 70+20+6+40 = ¥136，必须把 40 拆成「净留存 20 + 代门店支付 20」才能配平——这正是 B 口径复杂度的来源。

切换方式：新增配置 commission_base_mode = labor | gross，订单创建时固化 base_mode_snapshot；切换只影响新订单，历史订单按各自快照结算，禁止追溯改价。图 3 与第九章按方案 A 出稿。

3.2 合作接入模式（推荐路径）

阶段动作要点与产出
① 签约与品牌总部 / 区域管理方洽谈签署平台—品牌合作协议：接入门店范围、工位服务费口径、结算周期、责任边界、数据与影像使用范围、商标授权范围与期限、退出与数据清理；明确门店是否可自行开通账号
② 导入批量导入门店主数据门店名称、地址与经纬度、营业时间、工位数量、联系人、资质文件、结算账户；导入后状态 = 待审核
③ 审核后台逐店审核与协议绑定核验营业执照、场地与工位、场地责任险、结算账户进件；绑定协议版本与工位费档位；审核通过才置为「可接单」
④ 开通发放门店端账号与子账号店长主账号 + 前台/工位员子账号，按 RBAC 分配权限；首次登录强制改密与隐私/操作规范确认
⑤ 运营档期维护与对账门店维护工位档期与营业状态；平台按单锁位、按单结算；T+1 对账，差异挂起 ≤24h 并告警
⑥ 退出暂停 / 退店停止派单、结清未结算款项、冻结账号、按协议清理数据与影像；历史单据按留存期归档
为什么不建议「单店私自接入」：连锁门店多为加盟体系，单店未必有权代表品牌签平台合作协议，也可能无权使用品牌标识；逐店私签会带来商标授权瑕疵、履约责任不清与结算主体不一致。先总部/区域签约再批量导入，是风险最低的路径；若试点期只能单店合作，须逐店核验授权文件并把「品牌展示」限制为中性描述。

3.3 门店准入资质清单

项要求校验与留痕
主体资质营业执照（经营范围含汽车清洗/美容/维修）、门店实拍与门头照后台人工审核 + 文件存档，审核人/时间留痕；到期前 N 天提醒复核
场地与工位可用洗车工位数、营业时段、场地地址与经纬度、进车动线档期容量以此为上限；地址用于派单距离计算与导航
责任保障场地责任险 / 公众责任险（建议，须与保险合作方确认与 L1 的衔接）保单号与有效期登记，过期自动暂停接单
结算主体对公结算账户或经营者账户、开票信息、分账接收方进件材料V1 仅登记并写模拟台账；真实分账进件为上架阻塞项
协议与授权平台—门店服务协议、工位费档位、商标授权文件（如展示品牌）协议版本号固化到订单 store_snapshot，禁止追溯改价
账号店长手机号 + 实名；子账号按角色分配门店端 RBAC，最小权限，操作日志 ≥180 天

5.2 模式甲 / 模式乙对比（H2 的展开）

模式谁洗车对计价与责任的影响结论
甲洗车工带车到店，自行完成洗车；门店提供工位、水电、工具与场地管理M = 工位场地服务费（金额较低）；T2 车损以作业方（洗车工）为主、叠加门店场地管理责任；与 v1.0/v2.0 的洗车工主体、计价与保险链路一致，合作门槛低默认
乙洗车工仅取送车，门店技师完成洗车M = 门店洗车服务费（金额较高）；洗车工实收应只对应取送车劳务，抽成基数 L 需重设；T2 责任主要归门店；需门店排班与技师产能，接入复杂度显著上升V1.1

推荐甲的理由：保持「洗车工 = 服务主体」这一前序版本的核心设定，40% 抽成、免佣卡、评分治理、代驾授权与保险链路无需重构；门店端只需管工位、验收与评价，最容易被连锁门店接受。若试点发现门店希望自营洗车，再按模式乙单独立项评估，不在本期范围内。

6.2 事故上报与保险覆盖

  1. 任一段发生刮蹭 / 车损：洗车工或门店一键上报 → 上传现场影像 → 系统冻结该单结算（FROZEN）并通知后台与客服。
  2. 后台按上报所属段落自动调取该段证据集（E1/E2、E2/E3 或 E3/E4）+ 轨迹 + 交接单，形成调解材料包。
  3. 保险报案（V1 为模拟记录）→ 人工调解定责 → 按结果释放冻结、调整结算或走赔付流程；全程留痕 ≥180 天。
  4. 保险覆盖窗口必须包含 T1 + T2 + T3 全段；v1.0 的 L1 每单强制统保继续有效，保单未回写禁止派单。T2 门店作业段是否可保、是否需叠加门店场地责任险、用户商业车险对非约定驾驶人是否加扣免赔，均须由保险合作方书面确认，列为遗留决策点。

八、门店拉黑机制

8.1 定义与边界（最容易设计错的地方）

门店拉黑 ≠ 平台封号。门店拉黑是局部生效：该洗车工不能再接该门店的订单（派单过滤条件），仍可接其他门店订单；平台封号是全局终止服务，必须走 v1.0 的证据 + 人工复核 + 书面告知 + 申诉通道。两者共用证据链，但处置层级、审批人与申诉对象不同，禁止混淆。
环节规则（建议值，均可配置）约束

九、三方结算体系

9.1 口径定义（方案 A）

符号含义口径说明
S洗车服务费结构化分项计价的实际金额；不含保险费、代垫费用、券额
M门店工位费从 S 中划出，按门店协议版本取档；代收代付、不抽成；订单固化 store_fee_snapshot
L洗车工劳务收入L = S − M，为本版抽成基数
r有效费率基准 40%；持有效免佣卡时取卡费率；由 rate_snapshot + card_snapshot 决定
B保险费L1（强制）+ L2（加购），代收代付、不抽成、全额转付保险合作方
D代垫费用停车费等，凭凭证实报实销，全额转付洗车工、不抽成
C优惠券金额平台营销成本，用户少付、平台补足，不减少洗车工与门店结算
P用户实付P = S + B + D − C

9.2 公式、恒等式与平台收支

分账公式：platform_fee = L × r；worker_net = L − platform_fee + D；store_net = M。
分账恒等式（现金口径）：P + C = worker_net + store_net + B + platform_fee。
推导：P + C = S + B + D = (M + L) + B + D；右侧 = (L − L·r + D) + M + B + L·r = M + L + D + B；两侧相等，恒等式成立。
平台净留存 = platform_fee = L × r；券额 C 与免佣减免额（相对基准抽成的让利）作为平台权益成本单独记账，不进入分账指令；卡费收入按卡期确认。

若评审选择方案 B，需把 platform_fee 拆为「毛运营费 S×r / 净留存 S×r − M」，并把 store_net = M 记为平台成本支出；恒等式改为 P + C = worker_net + store_net + B + platform_net。图 3 与下方示例均按方案 A。

14.2 上架切换清单（相对 v1.0/v2.0 追加）

  1. 完成品牌总部/区域合作协议与商标书面授权，明确展示范围与期限；未授权前门店端与宣传物料保持中性命名。

  4. 税务与发票路径：门店工位费的开票主体、税目与灵活用工税务方案，由财务/法务出具意见。
  5. 切换 payment.mode 至真实渠道前清空全部模拟台账、隔离测试数据，并跑通同一套支付网关契约测试。
