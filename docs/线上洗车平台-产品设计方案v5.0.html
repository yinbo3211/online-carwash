二、概念消歧与三级价格锚点

必须先消歧：「上门服务必然比到店贵」在本文档里存在两种可能的「到店」——① 用户自己开车去洗车店（市场到店自助）；② 本平台 v1.0~v4.0 的「洗车工上门取车 → 开到合作门店工位洗 → 还车」（STORE 取送到店）。两者价位差一个量级，不消歧会直接导致定价错误。

2.1 三级价格锚点

锚点履约形态谁分账车辆是否离场相对价位本平台是否提供
① 市场到店自助（基准）用户自驾到洗车店，门店工位洗门店 1 方用户自驾最低否，仅作可接受性对照
② 平台 · 取送到店 STORE洗车工取车 → 门店工位洗 → 还车平台 + 洗车工 + 门店（3 方）是（代驾取送）显著高于 ①是（v1.0~v4.0 已定）
③ 平台 · 纯上门 ONSITE门店接单 → 派洗车工带设备到用户指定地点洗平台 + 洗车工 + 门店（3 方）否（车不离场、全程可见）高于 ②是（v5.0 新增）

为什么平台两种形态都显著高于市场到店自助：市场到店只有门店一方收取洗车费；平台形态额外包含取送车代驾或移动作业、每单强制保险、平台运营费与洗车工劳务，且是三方分账。这正是用户「因为三端都要赚钱」的成立口径。

为什么 ③ 还要高于 ②：ONSITE 不收取代驾取送车费 A（¥18），但新增上门附加 V（¥20）、服务项上门系数（工时上浮 1.25×、无专业工位导致效率损失）、设备与污水回收摊销（含在门店组织费 G 中），并让洗车工承担不计入计价时长的通勤。溢价来自增量成本与「车不离场、无代驾挪车风险」的价值，不是把三方利润重复叠加一遍。

公开资料对「上门比到店贵」的口径并不一致：有整理给出「比到店贵 20%~50%」（基础洗上门 30–60 / 到店 20–40），也有 2026-11 报道称「基础精洗上门 30–60 与到店 25–40 基本持平」。本文档只取「上门 ≥ 到店、通常有溢价」这一定性结论作对照，不引用任何媒体区间作为定价依据；本平台价格一律由成本模型与三端底线推导。

三、门店产能状态中心（空位与自动改状态）

3.1 两个维度、一个状态中心

门店能否接单不是一个是非题，需要拆成两个独立计数的维度，由统一的 StoreCapacity 服务持有状态；状态机是唯一写入方，派单引擎只读。

维度服务对象计量单位关键字段
Bay 工位STORE 取送到店单（外部洗车工带车来洗）工位数 × 时段档期bay_id、状态、锁位订单、时段、置信度
Crew 上门班组ONSITE 上门单（门店派工外出）可派班组数、设备套数、服务半径crew_id、available_crews、equipment_sets、radius_km

两维度独立计数的目的：同一门店可同时承接到店单与上门单，任一侧产能耗尽只停止对应类型订单，避免「一店一开关」造成整体误停或超卖。

3.2 状态源三级（L0 / L1 / L2）

级别实现方式自动改状态外部依赖合规门槛V1 取舍
L0 手动门店端一键「有空位 / 已满 / 暂停接单」，手动设可派班组数与设备套数否（人工）零无必做人工最终真值、所有自动化的兜底
L1 事件 + 心跳锁位成功→已锁定；E2 交接→作业中；E3 离店 / 锁位超时→自动回空闲；心跳断连→离线未知并停止派单是仅订单事件与门店端心跳，零硬件低（无图像采集）推荐默认已满足「软件自动更改状态」
L2 车位传感器地磁 / 超声 / 红外对射判占用；或边缘侧视觉只回传「占用 / 空闲」布尔值 + 置信度是硬件 + 门店授权 + 边缘设备高（见 3.3）V2 可绕过有替代方案，缺失可降级上线

3.3 选型修正：为什么不建议「直接接监控」

这是本版最重要的技术选型修正。用户提出「直接接监控让软件判断空位」，但把门店安防监控画面用于「工位是否空闲」的商业调度，在现行规则下不成立，因此不能直接照字面实现。
依据要点对本设计的约束
《个人信息保护法》第 26 条公共场所安装图像采集、个人身份识别设备，应为维护公共安全所必需、设显著提示标识；所收集的个人图像、身份识别信息原则上只能用于维护公共安全目的，取得个人单独同意的除外「判断工位空位、自动调度订单」属商业目的，非公共安全必需；不得径直复用公共安全视频画面
《公共安全视频图像信息系统管理条例》（国务院令 799 号，2025-04-01 施行）除负有经营管理责任 / 安全防范义务的单位为维护公共安全所必需外，其他单位个人不得在公共场所安装图像采集设备；保存期届满应删除；违法安装可没收设备、罚款、责令停业整顿平台不是该视频系统的管理单位，无权为商业判空调取或留存门店视频
《个人信息保护法》第 6 条（最小必要）、第 24 条（自动化决策）处理个人信息应限于实现目的的最小范围；通过自动化决策作出对个人权益有重大影响的决定，个人有权要求说明并拒绝仅通过自动化决策作出决定自动改状态若影响门店接单收入或洗车工派单，须保留人工覆盖、说明与拒绝通道

合规的替代路径（按优先级）：

  1. L1 事件驱动状态机：由订单生命周期与心跳推导状态，本就不需要任何摄像头，且比视觉判空更可靠（工位「有没有空位」的真值是「有没有被订单锁定」，不是「画面里有没有车」）。这才是 V1 实现「软件自动更改状态」的正解。
  2. L2 非图像传感器：地磁 / 超声 / 红外对射车位检测器只输出占用布尔值，不产生个人图像，合规成本最低。
  3. 若门店坚持用既有摄像头：只允许在门店边缘侧完成占用二值判断，平台只接收布尔值 + 置信度 + 时间戳；不回传、不存储、不展示任何图像；不做人脸识别、不做车牌识别、不做人流统计；须店主书面授权、显著提示标识、目的限定与单独同意，并保留一键关闭。上述条件任一不满足，接入即判定为不可上线。

四、门店自主接上门单（ONSITE）

4.1 角色与业务定义

门店在 ONSITE 单中不再是「提供工位」，而是工单承接方 + 属地派工方 + 质量兜底方 + 客诉首责方：门店从上门单大厅自主接单，指派一名平台注册洗车工携设备上门；门店提供设备与耗材调度、对服务结果兜底、对客诉先响应。洗车工仍是独立收益方，保证「三端都赚钱」成立。

4.2 接单前置校验（七项，全部通过才可进入派单池）

#校验项失败处理
1Crew 可派班组数 ≥1 且设备套数 ≥1该店不展示此单，不占用抢单窗口

5.2 STORE 分账模型（基线，不漂移）

S = A + W（A 取送车费 ¥18、W 洗车服务项）；M 门店工位费按档位先划出、不抽成；L = S − M；platform_fee = L × 40%；worker_net = L × 60% + 代垫；store_net = M；P = A + W + B − C。
恒等式：P + C = worker_net + store_net + B + platform_fee（保险费 B 与工位费 M 均为代收代付，不进抽成基数）。

5.3 ONSITE 分账模型（新增）

W_on 上门服务项价目（含上门系数）；V = ¥20 上门移动作业附加（全额补偿洗车工通勤与移动作业，先划出不抽成）；G = ¥18 门店包干组织费（派工 / 设备调度 / 质量兜底，先划出不抽成）；L_on = W_on − G；platform_fee = L_on × r_on；worker_net = L_on × (1 − r_on) + V；store_net = G；P_on = W_on + V + B − C。
恒等式推导：worker_net + store_net + B + platform_fee = L_on(1 − r) + V + G + B + L_on·r = L_on + V + G + B = (W_on − G) + V + G + B = W_on + V + B = P_on ✓ 与 STORE「M 先划出」的口径完全一致。
